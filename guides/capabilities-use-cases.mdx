title: "Capabilities use cases"
description: "Recipes that show what changes in an agent's behavior when you add, remove, or narrow a capability"
---

Each recipe below starts from a goal, shows the call, and explains what the
agent does and does not do. They go from the simplest (one message) to the most
complete (a thread policy plus per-message changes).

If you want the definitions first, read [Capabilities](/guides/capabilities).

## Before you start

Every snippet runs inside an `AsyncCominty` context and uses these
placeholders. Replace them with your own values.

```python
import asyncio

from cominty_sdk import AsyncCominty

AGENT_ID = "__cominty_agents::agent.chat"  # or the id of your own agent
SOURCE_ID = 2292  # copied from platform.cominty.ai/knowledge, the ID of a source
OTHER_SOURCE_ID = 2293  # a second source
SKILL_ID = "your-skill-id"  # copied from the Skills page of the platform


async def main():
    async with AsyncCominty() as client:  # COMINTY_API_KEY + COMINTY_USER_ID
        ...  # paste a recipe here


asyncio.run(main())
```

<Tip>
  Not sure where to find an id? See [Find your ids](/guides/capabilities#find-your-ids).
</Tip>

## The example agent

Every recipe starts from the same agent: `agent.chat`, the built-in Chat agent.
It has no capabilities saved, so every capability is `always`, with no filter.
The recipes work the same with Hive. They do not apply to Planner, which
ignores capabilities. See [Built-in agents](/guides/agents).

| Capability | Activation | Filter | What it means |
| ---------- | ---------- | ------ | ------------- |
| `web` | `always` | - | The agent may search the web on any message |
| `indexed_documents` | `always` | `ALL` | Every source and every document |
| `mcp` | `always` | `ALL` | Every integration available to the user. The recipes assume Linear and Slack. |
| `skills` | `always` | `ALL` | Every skill available to the user |
| `image_generation`, `video_generation`, `music_generation` | `always` | - | The agent may generate media on any message |
| `memory` | - | - | Off: the built-in agent has no namespace |

Each recipe opens with its **Starting point**: what the agent has before the
call, and what the recipe changes.

Where a recipe says "the agent can", it means the agent can use it if the
question calls for it. A capability that is on does not force the agent to use
it. That is why the messages name what they want ("in my documents", "without
searching the web"): the scope enforces, the words guide the agent. See
[Help the agent follow a scope](/guides/capabilities#help-the-agent-follow-a-scope).

<Note>
  If you use your own agent, check its capabilities on the **Agents** page
  first. A scope on a capability your agent sets to `never` returns a 422. So
  does `enabled=False` on a capability it sets to `on_request`.
</Note>

## Recipe 1: skip the web for one message

**Goal:** "Answer this question from what you know. Do not search the web."

**Starting point:** the example agent. `web` is `always`, so the agent may
search the web on any message. This recipe turns it off for one message.

<Tabs>
  <Tab title="Python SDK">
    ```python
    from cominty_sdk import MessageScope, WebScope

    run = await client.chat.start(
        agent_id=AGENT_ID,
        message="Without searching the web, what is the MCP protocol? Two sentences.",
        message_scope=MessageScope(web=WebScope(enabled=False)),
    )
    print(await run.text())

    # Next message, no scope: web search is available again.
    follow_up = await client.chat.send(
        run.thread.id,
        agent_id=AGENT_ID,
        message="Now check the latest version of the spec online.",
    )
    print(await follow_up.text())
    ```
  </Tab>
  <Tab title="HTTP">
    ```bash
    curl -X POST "https://ds.cominty.com/chat" \
      -H "x-cominty-token: $COMINTY_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "message": {
          "content": "Without searching the web, what is the MCP protocol? Two sentences.",
          "scope": {"web": {"enabled": false}}
        },
        "options": {
          "agent_id": "'"$AGENT_ID"'",
          "user_id": "'"$COMINTY_USER_ID"'"
        }
      }'
    ```
  </Tab>
</Tabs>

▶ [`examples/11_capabilities.py`](https://github.com/cominty/python-sdk/blob/main/examples/11_capabilities.py)

**Expected behavior:** The agent answers the first question from what it
already knows. Web search is off for this message, and the message says so. The
agent still sees the web tool, but a call to it would be refused. It still has
every other capability: it could search your documents or call Linear if the
question needed it. On the second message you sent no scope, so web search is
back, and the message asks for it ("online").

**Goal:** "Summarize only the 2024 board deck."

## Recipe 5: a thread that never uses the web

**Goal:** "Support conversations must never browse the web."

**Starting point:** the example agent. `web` is `always`. This recipe removes it
from the thread.

This time the rule is for the whole thread. Use `thread_capabilities` with
`activation="never"`.

<Tabs>
  <Tab title="Python SDK">
    ```python
    from cominty_sdk import (
        AgentCapabilities,
        APIError,
        MessageScope,
        WebCapability,
        WebScope,
    )

    run = await client.chat.start(
        agent_id=AGENT_ID,
        message="What is the refund window for annual plans?",
        thread_capabilities=AgentCapabilities(
            web=WebCapability(activation="never"),
        ),
    )
    print(await run.text())

    # A later message cannot bring the web back.
    try:
        await client.chat.send(
            run.thread.id,
            agent_id=AGENT_ID,
            message="Check a competitor's pricing online.",
            message_scope=MessageScope(web=WebScope(enabled=True)),
        )
    except APIError as exc:
        print(exc.status_code, exc.detail)  # 422
    ```
  </Tab>
  <Tab title="HTTP">
    ```bash
    curl -X POST "https://ds.cominty.com/chat" \
      -H "x-cominty-token: $COMINTY_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "message": {"content": "What is the refund window for annual plans?"},
        "options": {
          "agent_id": "'"$AGENT_ID"'",
          "user_id": "'"$COMINTY_USER_ID"'",
          "capabilities": {"web": {"activation": "never"}}
        }
      }'
    ```
  </Tab>
</Tabs>

▶ [`examples/11_capabilities.py`](https://github.com/cominty/python-sdk/blob/main/examples/11_capabilities.py)

**Expected behavior:** The agent answers from your documents and its own
knowledge. It has no web search tool on any message of the thread: with
`never`, the tool is not installed, unlike a scope that only switches it off.
Asking for web search on a later message does not work: the request is
rejected with a 422 `APIError` before the agent runs, because the thread does
not have the capability to turn on. The other capabilities (documents, MCP, and
so on) keep the agent's values, because you only redefined `web`.

## Recipe 6: generate an image only when asked

**Goal:** "Let the agent draw, but only when the user asks for it."

**Starting point:** the example agent. `image_generation` is `always`, so the
agent may draw on any message. This recipe sets it to `on_request` for the
thread.

Use `on_request`. The capability is installed but off until a message turns it
on.

<Tabs>
  <Tab title="Python SDK">
    ```python
    from cominty_sdk import (
        AgentCapabilities,
        ImageGenerationCapability,
        ImageGenerationScope,
        MessageScope,

    run = await client.chat.start(
        agent_id=AGENT_ID,
        message="Describe a simple onboarding flow in three steps.",
        thread_capabilities=AgentCapabilities(
            image_generation=ImageGenerationCapability(activation="on_request"),
        ),

    print(await run.text())

    drawing = await client.chat.send(
        run.thread.id,
        agent_id=AGENT_ID,
        message="Generate an image of that flow, drawn as a diagram.",
        message_scope=MessageScope(
            image_generation=ImageGenerationScope(enabled=True),
        ),
    )
    print(await drawing.text())

    # Next message, no scope: image generation is off again.
    text_only = await client.chat.send(
        run.thread.id,
        agent_id=AGENT_ID,
        message="Now add a fourth step, in words.",
    )
    print(await text_only.text())
    ```
  </Tab>
  <Tab title="HTTP">

    ```bash
      -H "x-cominty-token: $COMINTY_API_KEY" \

          "content": "Generate an image of that flow, drawn as a diagram.",
    ```

### What `ALL` and invalid values do

A filter you leave out means no restriction. `ALL` says it explicitly.

```python
from cominty_sdk import ALL, McpCapability

McpCapability(activation="always")                  # every connection
McpCapability(activation="always", connections=ALL)  # same thing
```

Three values look like "no filter" but are errors. The SDK raises
`InvalidParams` before it sends anything:

```python
from cominty_sdk import InvalidParams, McpCapability

for bad in (None, [], ["*"]):
    try:
        McpCapability(activation="always", connections=bad)
    except InvalidParams as exc:
        print(exc)
```

| Value | Why it is refused | What to pass instead |
| ----- | ----------------- | -------------------- |
| `None` | Ambiguous | `ALL` for no restriction |
| `[]` | An empty list is ambiguous | `ALL`, or turn the capability off |
| `["*"]` | `"*"` inside a list is not a wildcard | `ALL` on its own |

A filter together with `activation="never"` or `enabled=False` is also refused,
because those states take no filter.

<Warning>
  A capability you pass replaces the agent's version of it entirely. If the
  agent limits documents to two sources and you pass
  `IndexedDocumentsCapability(activation="always", document_ids=[...])`, the
  agent's `source_ids` are gone. Capabilities you do not pass keep the agent's
  value: web stays on until you pass `WebCapability(activation="never")`. See
  [Override an agent for one thread](/guides/capabilities#override-an-agent-for-one-thread).
</Warning>

## Recipe 8: one memory per customer

**Goal:** "Remember each customer's preferences, and never mix customers up."

**Starting point:** the example agent. It has no memory namespace, so it has no
memory. This recipe gives each thread one.

Memory is a capability. Give each thread a namespace that includes the customer
id.

<Tabs>
  <Tab title="Python SDK">
    ```python
    from cominty_sdk import AgentCapabilities, MemoryCapability

    customer_id = "acme"

    run = await client.chat.start(
        agent_id=AGENT_ID,
        message="Remember that this customer prefers short answers.",
        thread_capabilities=AgentCapabilities(
            memory=MemoryCapability(
                activation="always",
                namespace=f"customer-{customer_id}",
            ),
        ),
    )
    print(await run.text())

    # The namespace is frozen for the thread: no need to repeat it.
    follow_up = await client.chat.send(
        run.thread.id,
        agent_id=AGENT_ID,
        message="What do you remember about this customer?",
    )
    print(await follow_up.text())
    ```
  </Tab>
  <Tab title="HTTP">
    ```bash
    curl -X POST "https://ds.cominty.com/chat" \
      -H "x-cominty-token: $COMINTY_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "message": {"content": "Remember that this customer prefers short answers."},
        "options": {
          "agent_id": "'"$AGENT_ID"'",
          "user_id": "'"$COMINTY_USER_ID"'",
          "capabilities": {
            "memory": {"activation": "always", "namespace": "customer-acme"}
          }
        }
      }'
    ```
  </Tab>
</Tabs>

To run a thread with no memory at all, even if the agent has a namespace:

```python
thread_capabilities=AgentCapabilities(
    memory=MemoryCapability(activation="never"),
)
```

▶ [`examples/11_capabilities.py`](https://github.com/cominty/python-sdk/blob/main/examples/11_capabilities.py) ·
[`examples/09_memory.py`](https://github.com/cominty/python-sdk/blob/main/examples/09_memory.py)

**Expected behavior:** The agent has memory tools on this thread. It writes the
preference to a file in the `customer-acme` namespace, and reads it back on the
next message. A thread started for another customer uses a different namespace,
so it cannot see this file. With `activation="never"`, the agent has no memory
tools and writes nothing, even if the agent normally has a namespace. A
follow-up cannot change the namespace: start a new thread to use another one.

Read what the agent stored with [`client.memory`](/guides/memory-namespaces).

## Recipe 9: lock the thread, then focus each message

**Goal:** "A support thread with a fixed policy, where each question can narrow
it further."

**Starting point:** the example agent. Every capability is `always`, with no
filter. The thread replaces web, documents, and MCP with its own policy. Each
message then narrows that policy.

Combine both levels. The thread sets the policy once. Each message narrows it
without ever going beyond it.

<Tabs>
  <Tab title="Python SDK">
    ```python
    from cominty_sdk import (
        AgentCapabilities,
        APIError,
        IndexedDocumentsCapability,
        IndexedDocumentsScope,
        McpCapability,
        McpScope,
        MessageScope,
        WebCapability,
    )

    run = await client.chat.start(
        agent_id=AGENT_ID,
        message="Which plans include single sign-on?",
        thread_capabilities=AgentCapabilities(
            web=WebCapability(activation="never"),
            indexed_documents=IndexedDocumentsCapability(
                activation="always",
                source_ids=[SOURCE_ID, OTHER_SOURCE_ID],
            ),
            mcp=McpCapability(activation="on_request", connections=["linear"]),
        ),
    )
    print(await run.text())

    # Narrow to one source for this message.
    narrowed = await client.chat.send(
        run.thread.id,
        agent_id=AGENT_ID,
        message="In the first source only, which plans include single sign-on?",
        message_scope=MessageScope(
            indexed_documents=IndexedDocumentsScope(
                enabled=True,
                source_ids=[SOURCE_ID],
            ),
        ),
    )
    print(await narrowed.text())

    # Turn the on_request connection on for one message.
    with_linear = await client.chat.send(
        run.thread.id,
        agent_id=AGENT_ID,
        message="Check Linear: is there an open ticket about SSO?",
        message_scope=MessageScope(mcp=McpScope(enabled=True)),
    )
    print(await with_linear.text())

    # Going beyond the thread is refused.
    try:
        await client.chat.send(
            run.thread.id,
            agent_id=AGENT_ID,
            message="Search every source.",
            message_scope=MessageScope(
                indexed_documents=IndexedDocumentsScope(
                    enabled=True,
                    source_ids=[SOURCE_ID, 999999],
                ),
            ),
        )
    except APIError as exc:
        print(exc.status_code, exc.detail)  # 422
    ```

**Expected behavior:**

| Message | Web | Documents | Linear |
| ------- | --- | --------- | ------ |
| 1. No scope | Off, for the whole thread | Both sources | Off (`on_request`) |
| 2. `source_ids=[SOURCE_ID]` | Off | The first source only | Off |
| 3. `McpScope(enabled=True)` | Off | Both sources | On, for this message |
| 4. A source outside the thread | The request fails with a 422 | | |

Each scope applies to its message only. After message 2, message 3 searches
both sources again. The thread policy is the ceiling. A message can go down
from it, never above it.
